# Kaven Docker 0.2.1

Kaven Docker 0.2.1 hardens runtime storage, update installation, and the
release toolchain for the Windows desktop application.

## Highlights

- Use the standard application identity `Kaven-Docker`, bundle identifier
  `xyz.kaven.app.docker`, installation root
  `%LOCALAPPDATA%\Kaven\App\Kaven-Docker`, and data root
  `%LOCALAPPDATA%\Kaven\Data\Kaven-Docker`.
- Keep one desktop process as the persistence owner, with instance-owned
  temporary directories, stale-instance locking, and Windows atomic file
  replacement.
- Keep update discovery on `public.data.kaven.xyz`, support ordered signed
  artifact mirrors, and reject non-numeric or incomplete release versions.
- Pin the release build inputs, verify generated schemas, and strengthen
  dependency and release-identity checks.
- Update the development and release toolchain to Rust 1.99.1.

## Upgrade notes

The application does not automatically search for or move data from the old
`%LOCALAPPDATA%\Kaven\Kaven-Docker` directory. Before starting 0.2.1, close
every Kaven Docker process and move that directory to
`%LOCALAPPDATA%\Kaven\Data\Kaven-Docker`. Do not merge directories if the
destination already exists; preserve both and resolve the conflict manually.

The Windows credential-manager service name remains `kaven-docker`, so saved
registry and proxy passwords do not need to be copied to a new credential
namespace.

The pre-release three-file configuration layout inside the active data root
continues to migrate to the authoritative `config.json` format with recovery
journaling.

## Supported platform

This release is validated for 64-bit Windows and is distributed as a per-user
NSIS installer with a separate Minisign updater signature.
